# v1.0.0 公開前・実機チェック（KINA用）

対象: `simple-marugoto-zip` v1.0.0（v0.0.24からの機能変更なし）。v0.0.23までの確認済み項目は再実行不要。

## v0.0.24 追加の確認（KINA実機済み）

- [x] 新しいChrome環境で「手動」が初期選択。既存環境で以前「自動」を選んでいた場合は、その設定が維持される。
- [x] ZIP分割は「自動 / 500 MB / 1 GB / 500ファイル」。10ファイルは表示されない。
- [x] 自動分割の説明が「300 MBまたは300ファイル」になっている。閾値の実動作はオフライン回帰テストで確認済みなので、Xから300件を再取得する必要はない。
- [x] 設定タブから疑似429テストの操作欄がなくなり、ZIP・JSONの復元と全体JSONの保存はそのまま動作する。
- [x] 小規模アカウントで手動収集→完了→ZIP保存を一通り確認。必要な保存データは先に全体JSONで退避。

## 最初に（5分）

- [x] 普段のPCで全体JSONをエクスポートし、別の場所へコピーする。必要なZIPも手元に残す。
- [x] 既存の拡張は**削除せず**更新する。実際の `manifest.json` バージョンとポップアップの表示が一致すること。
- [x] 収集テストは少量・自分で管理するアカウントを優先。大量スクロールや本物の429誘発はしない。
- [x] `5ファイル（動作確認）` が初回設定であることを認識し、全件ZIP化の試験では `無制限` に切り替える。

## A. UIとアカウント切替

- [x] **A1 / 優先**: Xのプロフィール・`/media`・個別投稿から対象アカウントが正しく表示される。X以外のページでは誤収集しない。
- [x] **A2 / 優先**: ポップアップのボタン・状態・設定が一般的な表示倍率（100%、必要なら125%）で欠けず、不要な縦スクロールが出ない。
- [x] **A3 / 優先**: 件数1,000以上の確認を出すだけ（開始しなくてよい）。別アカウントへ移ると黄色の「確」が消え、元アカウントに戻すと再表示される。
- [x] **A4**: 収集数が100%に見えても最終確認中は理由が表示され、確認終了後に緑のZIP保存が有効になる。
- [x] **A5**: 青・緑の小型アイコン、黄色「確」、黄色「待」、完了後の緑「✓」が見分けられる。

## B. 収集・停止・疑似429

- [x] **B1 / 優先**: 手動収集を開始→ユーザー自身がX画面をスクロール→カウント増加→「収集を完了」→ZIP保存可能。拡張が勝手にスクロールしない。
- [x] **B2 / 優先**: 手動収集中に「停止」→再開。既取得分が消えず、同じメディアを二重登録しない。
- [x] **B3 / 優先**: 手動収集中に設定タブから**疑似429**→待機→約90秒後の復帰。手動モードのままで自動スクロールしない。※本物の429を狙って起こす必要はない。
- [x] **B4**: 手動収集中に対象Xタブを閉じる／Chromeを終了→再度開いて収集を再開。既取得数が維持される。
- [x] **B5 / 条件付き**: 自動収集の公開方針が確定した場合にのみ、小規模アカウントでレスポンス待ち・停止・完了を確認。Xの現行利用規則は別途公開ゲートで判断。

## C. ZIP保存と状態ファイル

- [x] **C1 / 優先**: 画像＋動画を `10ファイル / 無制限` で保存。`..._media_001.zip`、`..._media_002.zip` と連番になり、内部の `images/`・`videos/` が合っている。
- [x] **C2**: 同じ収集結果から画像のみ→動画のみも保存できる。`images` / `videos` ごとに新しい日時・001から始まり、OSの `(1)` 重複名が不要。
- [x] **C3 / 優先**: 初回の保存先選択後、分割ZIPは再選択なしに連続保存。保存の中断・再開でも、Chrome側の許可がある限り同じフォルダを使う。
- [x] **C4**: `5ファイル` 保存→再開→次の5件へ進む。前回のZIPが書き換わらず、保存済み／未保存の境界が正しい。
- [x] **C5 / 優先**: 各分割ZIP内に `ユーザー名/backup-state.json` がある。途中の001を復元したとき、002以降を保存済み扱いしない。
- [x] **C6**: ZIP中に別タブへ移動・元タブを閉じても処理が続き、完了 `✓` はポップアップを開くまで保持される。
- [x] **C7 / 任意**: 500ファイル／500 MB／1 GBやChrome Downloads方式へのフォールバックが必要なら、既存のオフライン試験または少量の実機テストで確認。Xへ再度大量アクセスしない。

## D. 差分バックアップ

- [x] **D1 / 優先**: 前回保存が完了したアカウントへ数件追加→「新規分をチェック」→新着だけ収集・ZIP化。
- [x] **D2**: 新規0件なら「新規なし」となり、既存の収集状態・ZIP進捗を復元する。
- [ ] **D3**: 差分チェックを途中停止して「前回に戻す」を押すと、差分開始前の状態に戻る（既存ZIPは消えない）。
- [ ] **D4**: ZIP未保存の差分が残っている間は、次の差分チェックで元のデータを上書きしない。

## E. バックアップ・復元・初期化（別PCが便利）

- [x] **E1 / 優先**: 全体JSONをエクスポート→空のChrome環境へドロップ→アカウント数・設定・「前回のつづき」等が復元される。
- [x] **E2**: 同じJSONを2回ドロップすると、既存アカウントはそのまま（重複や進捗巻き戻りなし）。
- [x] **E3 / 優先**: 分割ZIPの最後のファイルをドロップすると、そのアカウントだけ追加できる。以前のZIP本体が自動転送されるわけではない点も確認。
- [x] **E4**: 既存アカウント置換・全体置換は確認を表示し、「いいえ」なら現在のデータが維持される。「はい」は**テスト用PC／テストデータだけ**で確認する。
- [x] **E5 / 優先**: 設定ページの「すべて削除」→左「いいえ」で何も消えない。右「はい、削除する」なら本拡張だけ初期化し、ディスクのZIP・JSON、Chrome本体、他の拡張は残る。**テスト用PCのみ。**
- [x] **E6**: 全体JSON・ZIP内JSONをテキストで確認し、APIキー、トークン、Cookie、パスワード、保存先権限が混入していない。アカウント名・投稿ID・CDN URLは含まれるので、JSONはむやみに公開しない。
