# v1.3.16 複数画像の確認手順

2026-11-17 / X・Bluesky・Threads

## 更新

1. 収集・ZIP保存中の場合は、停止または完了してから更新します。設定からJSONバックアップを保存しておくと戻せます。
2. 今まで読み込んでいる拡張フォルダへ本版を上書きし、Chromeの拡張機能管理画面で拡張を再読み込みします。削除・新規登録は不要です。
3. **開いているXのタブも再読み込みしてください。** 古いページ内の収集コードは、ファイルの上書きだけでは入れ替わりません。
4. 小窓のバージョンがv1.3.16になったことを確認します。

## 用意する投稿と最初の確認

各SNSに5枚以上の画像を含む投稿を用意し、投稿URLと枚数を控えます。画像に1〜10などの番号があると、保存した中身の照合が容易です。

- 既に前回分をすべて保存済みなら「新規分をチェック」を使用できます。
- 初めてのアカウントなら通常の「メディアを収集」を使用します。
- Xの手動収集では、対象投稿を表示して下へスクロールし、読み込み後に「収集を完了」を押します。通常の新規分チェックは前回位置への到達で終了します。
- Bluesky・Threadsは既存どおりAPIで収集します。

収集後、ZIP保存前にも診断ログを一度書き出すと、取得と保存の問題を分けられます。

## 分割保存

「ダウンロードファイル数」を5ファイルにしてZIPを保存します。残りがあれば再開を繰り返し、対象投稿の全画像が入っているか確認します。10枚だけなら2回、20枚だけなら4回です。他の投稿も収集した場合は、その分も含まれます。

確認するのはZIPの数だけでなく、実画像の内容と枚数です。対象投稿の1〜最後の画像がそろい、引用元の画像をその投稿の添付として混ぜていないことを確認します。

保存先はこれまでどおり別タブで選択します。「サイトアクセス時は常に許可」を選んでいない場合、選択肢が出ない場合、許可内容が不明な場合は、連続保存が終わるまで選択タブを閉じないでください。

## 古い収集データの不足分を補う

前回分を保存してから「不足分を再収集」を押します。新規分チェックと異なり、前回の最新投稿で打ち切らず、再び読み込めた範囲から未登録のメディアを集めます。以前0件で完了していたアカウントも対象です。

- 前回の収集・ZIP情報を退避し、追加分だけを今回の保存候補にします。
- X手動モードでは確認したい範囲までスクロールして「収集を完了」を押します。
- 追加分のZIP保存前なら、停止・完了後の「前回に戻す」で取り消せます。ZIP保存後は取り消せません。
- 追加が0件なら前回の状態へ戻します。
- 既知のメディアキーが残っている画像は再度候補にしません。古いバックアップに個別キーが残っていない過去分は、再取得されることがあります。
- Xの画面が提供しない古い履歴まで取得できる機能ではありません。削除・非公開投稿や既存のダウンロード失敗を自動復旧する機能でもありません。

## 診断と制限

- X: 同じ投稿の4枚→20枚のような応答拡張で追加分を取り込みます。確認待ち中の応答は登録完了まで保持します。
- X: 自動巡回中および手動収集の完了操作で、画面の投稿IDと収集済みIDの比較を `x.dom.compare` に記録します。DOMから原本画像を直接追加する処理は入れていません。未一致は通信待ち・引用などでも発生し、欠落の確定ではありません。
- Bluesky: 新形式 `app.bsky.embed.gallery` の画像に対応。未知のgallery要素・不正な原本情報は停止して知らせます。
- Threads: 子メディアが複数ページに分かれる場合の追跡を追加。未知の子形式、ページ繰り返し、不正な配信先では正常完了にしません。

自動検証は模擬API・模擬画像バイト列によるものです。別途、実機でXの自分・他人の20画像投稿、Blueskyの自分の10画像投稿と分割保存、Threadsの自分の20画像・10画像投稿の実保存を確認しました。確認範囲と残る制限は [リリースノート](RELEASE_NOTES_v1.3.16.md) を参照してください。Xが未知のJSON形式を返すケースへの対応は、今回の対策だけで保証していません。

問題がある場合は、投稿URL・想定枚数・実際の保存枚数と、収集直後／保存後の診断JSONを確認します。必要に応じてZIP内の `backup-state.json` と照合します。診断JSONにはアカウント名・フォルダ名などを含みます。
