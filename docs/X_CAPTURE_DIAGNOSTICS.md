# v1.3.15 X通信・抽出前の診断版

v1.3.14では認識済みのメディア配列を主に診断していたため、投稿ごと認識できない場合を十分に追えませんでした。本版は監視起動と通信の受信、画像0件の応答も記録します。収集・重複除外のルールを修正する版ではありません。

## 短いテスト手順

1. 収集中なら停止し、読み込み元フォルダへファイル一式を上書きして、Chrome拡張機能画面で再読み込みしてください。
2. 対象のXタブも再読み込みしてください。古い監視処理を残さないために必要です。
3. 必要なら設定の「保存先・X収集の診断ログ」で「診断ログだけを消去」を押し、設定・ログ画面を閉じます。収集データの削除は不要です。
4. 直近に5枚以上の投稿があるアカウントで、最初の約20ファイル分を手動で収集して収集完了にします。自分の20枚投稿と、他人の5枚以上の投稿を比較することもできます。20件で自動停止する機能を追加したものではありません。
5. 収集直後に診断ログを一度書き出してください。監視の起動や通信の有無はZIPを作る前に分かります。
6. 実ファイルも確認する場合は、5ファイル保存を繰り返して対象分まで進めます。8枚投稿などは複数ZIPに分かれるので、投稿IDに付く番号（_1〜_8など）が全ZIPを合わせてそろうか確認してください。必要なら保存後のログも書き出します。

保存先の選択は別タブのままです。「常に許可」が未選択・不明な場合は、連続保存終了まで選択タブを残してください。

## 追加した記録

- x.capture.content_ready: 収集側の起動、版番号
- x.capture.hook_ready: X通信を監視する側の起動、版番号
- x.capture.request: 監視対象通信の開始
- x.capture.response: 応答、HTTP状態、JSON解析の成否、観察したオブジェクト数、投稿候補数、抽出件数
- 古い形式のlegacy情報がない候補、メディア配列がない候補、作者不一致・作者不明、処理済み投稿の除外件数
- 現在の収集状態・収集件数・画像数・動画数・最新と最古の投稿ID

今回提供された投稿ID 2121977622796353698 / 2121951663368159350 と8つの画像IDを固定の追跡対象にしています。通信データの文字列にそれらが含まれたかを確認し、対象候補の構造のキー名や除外理由を記録します。引用・参照URLなどにIDだけが含まれた場合も一致するので、ID一致だけで対象投稿の全文や画像一覧が届いたと断定はしません。

他のアカウントでも起動・通信・抽出件数・5枚以上の投稿の診断は利用できます。固定の追跡対象以外の画像IDを自動保存する機能ではありません。

## 注意

最新400イベントを保持します。長時間の収集・保存前に、短い収集の直後のログを取る方が有効です。新しい記録があることを示すため、v1.3.15の起動記録が必要です。古い記録しかない場合や通信監視側の起動がない場合も、そのログを共有してください。

画像本体・投稿本文・メディアURL・Cookie・トークンは追加診断の記録対象にしていません。記録するのは件数、状態、投稿ID、提供済みの対象画像ID、構造のキー名などです。ログにはアカウント名・保存先情報等も含むため、共有前に確認してください。自動で外部送信はしません。

配布ZIPにはverificationや試験版ごとのCHANGE-NOTESを含めません。検証用の保存先やログは開発作業領域に置きます。今回は独立した別モデルのレビューを依頼していません。
