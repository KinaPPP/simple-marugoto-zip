# X 新旧メディアUI両対応 — v1.1.1 検証版

> Chrome実機での新UI取得は未検証。正式リリースではなく動作確認用です。

## 方針

- 初期設定は「画像／動画に分かれた新UIから収集」ON、「プロフィールタブを旧表示に戻す」OFF。
- 旧表示を使う場合は、XのReact featureSwitchesで `responsive_web_profile_redesign_enabled` の判定のみfalseにする。他のフラグには触れない。
- 新UIの自動収集では、同一タブ・同一収集ジョブで `/media`（動画）→ `/media?filter=photo`（画像）を巡回し、既存の投稿ID＋メディア番号のキーで重複を除外する。
- 実効UIが旧表示と判定できたときは従来の1ページ収集。Control Panel for Twitterの旧UI設定がONでも原則そのまま動く。
- XがAPI名を変更する可能性を考慮し、**収集実行中に限り** GraphQL応答を広く解析する。対象ユーザーの投稿だけを採用する。Xに独自APIリクエストは発行しない。
- 収集対象のメディアAPI応答を確認できない場合、0件の完了扱いを避け、エラーとして停止する。
- 429や明示的な停止・再開は既存の状態管理を利用。ページ間の進捗段階は同一タブ内のsessionStorageにのみ記録する。
- 写真側で一時停止した後、同じタブの動画ページで再開操作をしても、保存された段階を優先して写真ページに戻す。初期のUI判定メッセージが先行して失われた場合も、収集開始時に再通知する。
- 新UIでの差分収集は**両ページの末尾を確認してから**完了する（画像を見落とす早期停止を避けるため）。大量アカウントでは時間がかかる。旧UIの早期終了処理は維持。
- 手動モードでは自動ページ切替をしない。利用者自身が必要なページを切り替える。
- X上のUI変更オプションを切り替えた場合は、Xのタブを再読み込みして反映する。

## 実機確認が必要な条件

1. Control Panelの「プロフィールタブを元に戻す」をOFFにする。新UIで動画・画像が分かれていることを確認。
2. シンプルまるごとZIPの初期設定（新UI収集ON／旧UI化OFF）で、画像・動画がある小規模アカウントを自動収集。**両方の件数が入り、0件完了にならず、ZIP化できることを確認**。
3. 動画0・画像ありのアカウントでも写真ページへ切替わるか確認。
4. ページ切替中の停止→再開と429時の状態が維持されるか確認。
5. 旧UI化ON／新UI収集ONでリロード後に1ページ収集できるか確認。
6. Control Panelの旧UI化ON／シンプルまるごとZIPの旧UI化OFFで重複巡回しないか確認。
7. 旧UI化OFF／新UI収集OFFは新UIで完全収集できない可能性があるため注意。

## 未確認事項

- 新UIのGraphQLレスポンス形式と操作名は、実機のNetworkログなしでは確定できない。
- XのReact内部構造やfeatureSwitchesは将来のUI改修で変化し得る。旧UI化の操作が無効になっても、デフォルトの新UI収集は独立して動く設計。
- カルーセルOFFは今回の旧UI化フラグとは別。オプションに含めない。

## オフラインで確認したこと

- 設定の初期値：新UI収集ON／旧UI化OFF。全体バックアップにもこの2項目を保存。
- Xの旧表示オプションが対象の機能フラグだけを書き換えること。収集開始時に実効UIを再通知し、旧表示で2巡目を行わないこと。
- 新UIの動画→画像の2ページ巡回。動画が0件でも画像へ進むこと。画像側から1回だけ収集完了通知を送ること。
- 画像側で一時停止した後、動画ページから再開しても画像ページへ戻ること。

これらは模擬レスポンス／模擬ページによる確認であり、実際のXの新UIから全件を収集できることの証明ではありません。実機テストが終わるまではこのビルドを正式版として配布しないでください。
