# シンプルまるごとZIP v1.3.0 — Threads実機検証記録

v1.3.0でThreads APIと3SNS向け管理機能を追加しました。外部認証サーバーはありません。本人アカウント中心の実機検証結果と、公開プロフィール取得に関する制限を記録します。

## 実装済み（オフライン検証対象）

- 自分のThreads投稿 `/me/threads` と、`threads_profile_discovery`権限の許可範囲での公開投稿 `/profile_posts` を順次収集。
- `IMAGE`／`VIDEO`／`CAROUSEL_ALBUM` の画像・動画URLを抽出。子投稿IDだけが返る場合は個別取得。再投稿Facade／文字投稿は収集対象外。
- OAuthトークンは `chrome.storage.local` にのみ保存し、API通信ではBearerヘッダーで送信。API応答の `paging.next` URLを保存・追跡せず `after` カーソルのみ保存。
- Threadsの長期トークンの手動更新と期限前の自動更新（デフォルトON、残り30日目安）。PCがオフの間は更新できず、期限切れの場合はユーザーによる再接続が必要です。
- ZIP分割、種類別ZIP、バックアップ状態JSON、停止・再開、差分取得、429時の安全停止は既存共通処理を利用。
- SNS別・個別アカウントのJSON保存／選択復元、選択削除。認証情報はバックアップへ出力されません。
- MV3 Service Workerが途中で再起動しても、Threads／Blueskyは最後に確定したページカーソルから自動復旧します。ページを再取得した場合もメディアキーで重複を除外します。
- 復元は処理対象をアカウント単位で判定します。Threads収集中でも別のBlueskyアカウントなどは復元可能ですが、処理中の当該アカウント上書きと全体置換は拒否します。

## 実機確認済み

- 本人アカウントで2,825件（画像2,752／動画73）を最後まで収集。途中停止し、約30分後に同じ位置から収集再開できることを確認。
- 分割ZIPを10個まで保存。004.zip内の `backup-state.json` をリセット後に読み込み、005.zipから連番で再開して010.zipまで完走。
- 初期テスト版010.zipは取得失敗1件を含むため `archive_paused / imported_incomplete` と誤記録されていたが、互換補正後は全件処理済みとして `archive_complete` に復元する。
- 同010.zipのように取得失敗が残る最終ZIPでも、全項目を処理済みなら失敗履歴を残したまま次回の「新規分をチェック」へ進める。1件の取得失敗で差分機能が永久に塞がれないことを確認する。
- 新しいMeta App ID / App Secretから「Threadsトークン 取トーくん」で長期トークンを取得し、まるごとZIPへ新規登録した状態から本人アカウントの全件収集を開始できることを確認。
- 最終010.zipを単独復元すると即座に「ZIP保存完了」と表示され、不要な011.zipを作らないことを確認。
- 010.zip復元後の差分チェックで新規画像3件を検出し、新しい日時の001.zipとして保存。さらにその差分001.zipだけをリセット後に復元して、今回3件／累計2,828件として復元できることを確認。
- Threads収集中に別のXアカウントを収集・ZIP保存できることを確認。API収集中のService Worker再起動復旧と別SNS復元のスコープ制御はオフライン回帰テストでも検証。

## 制限・未確認事項
- MetaのStandard Accessでは公開プロフィール取得先が制限される場合があります。一般アカウント収集には審査・Advanced Access条件が関係します。現時点の実機確認は本人アカウント中心です。
- Threadsの署名付きCDN URLは期限切れになることがあります。期限切れ後は保存済みメタデータだけで再ダウンロードできない場合があります。
- 他人の引用投稿・再投稿のメディア、リンクカード画像、削除済み・非公開メディアを取得する仕様はありません。
- オフラインの429模擬試験は制限回避を保証するものではありません。実際に429が出たら待機時間を守ってください。
- App Secret・アクセストークン・Graph APIの `paging.next` をGitHub／チャット／不具合報告へ載せないでください。ページカーソルは診断時にも伏せて構いません。

## v1.3.0 実機スモークの推奨順序

1. **全体JSONを退避**してから既存拡張をv1.3.0へ更新。設定タブで本人の長期トークンを登録。
2. Threads本人の少量投稿で `IMAGE`、`VIDEO`、`CAROUSEL_ALBUM` の件数を確認。ZIPを最大5件で作り、解凍して動画再生・画像表示。
3. 途中停止→再開、配信URL期限切れ時のエラー表示を確認（意図的な大量リクエストは不要）。
4. Threads＋X＋Blueskyの全体バックアップから、**別のテスト用Chromeプロファイル**へ部分復元。Threads認証情報が移植されないことを確認。
5. 選択削除はテスト用アカウントだけで実施。認証とその他の収集状態が残ることを確認。
6. Threadsを数百件収集中に `chrome://extensions` のService Workerを停止し、1分程度以内またはポップアップ再表示後に収集が続くことを確認。完了後の総件数と重複がないことを確認。
7. Threads収集中に、別のBlueskyアカウントZIPを設定画面から復元。Threadsが継続したままBlueskyだけ復元されることを確認。

オフライン：`node tests/threads-provider.test.cjs` および `node tests/*.cjs` の既存テスト。テスト用のダミートークン以外の認証情報をソースに含めないこと。
