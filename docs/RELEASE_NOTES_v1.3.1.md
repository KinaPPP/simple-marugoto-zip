# シンプルまるごとZIP v1.3.1 — 第三者QAフォローアップ修正

v1.3.0正式公開後の第三者コードレビューで確認された、状態管理・差分・ZIP再開まわりの不具合を修正するパッチ版です。新しいSNS機能の追加ではなく、保存漏れ・混在・競合を防ぐ安全性強化が中心です。

## 主な修正

- ZIP再開順序をメディアキーで固定し、収集再開後の並べ替えによる保存漏れを防止。
- Threads収集を認証ユーザーIDへ固定し、収集中の別ユーザートークン切り替えを拒否。
- ZIP保存を単一ジョブとして排他制御し、別アカウントの開始・停止が他ジョブへ干渉しないよう修正。
- Threads差分の基準投稿が削除されても、前回スナップショットの既知投稿を境界として利用。
- 収集再開後に増えたメディアが未保存なら、旧ZIPの完了状態だけでは次の差分チェックへ進めないよう変更。確定済みメディアキーを累積記録し、現在の全メディアが保存処理済みかを判定。
- `itemKeys` の無い旧版バックアップでは現在の並び順から固定順序を推測せず、順序不明の進行済みZIPは安全側で再保存。
- Threadsで差分境界を確認できない場合は未確定候補として停止し、通常ZIP保存と累計加算を禁止。「前回に戻す」で安全に復帰可能。
- 最終ZIP内の `backup-state.json` に今回の確定済みメディアキーも反映し、最後のZIP単体から復元した後も差分チェックを継続可能に修正。分割途中のZIPには、その時点まで処理済みのキーだけを記録。
- 旧版で画像／動画を別々に保存していた場合、完了済みarchiveに記録された明示的な `itemKeys` を新形式の `savedItemKeys` へ安全に移行。順序や対象が不明な旧状態は推測しない。
- 分割ZIPの最後が取得失敗だけになった場合でも、最終状態を記録したcheckpoint専用ZIPを生成。最新ZIPから復元した処理位置・失敗件数・差分開始可否をローカル状態と一致させ、checkpoint保存に失敗・キャンセルした場合は未確定進捗を確定しない。
- ZIP保存の停止操作で未確定チャンクを破棄する場合も、処理位置だけでなく失敗件数・失敗一覧・進捗を直前の確定済みcheckpointへ戻す。再開時に成功した項目へ古い失敗記録を残さず、確定済みZIP内の過去失敗だけを維持する。

## テスト

第三者QAの指摘は先に再現テストを追加し、修正前に失敗することを確認してから実装しています。修正後は `tests/*.cjs` 全件と、全JavaScriptの `node --check` を実行します。

実サービス側のAPI応答やChrome実機でのタイミング差まではオフラインテストで保証できないため、公開前に短い実機スモークを推奨します。
