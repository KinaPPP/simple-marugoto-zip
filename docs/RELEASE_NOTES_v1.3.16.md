# v1.3.16 — 複数画像投稿の収集対応

X・Bluesky・Threadsの複数画像投稿について、画像の取りこぼし対策を追加しました。

## 主な変更

- Blueskyの新しいgallery形式に対応し、5枚以上の画像を含む投稿の原本画像を取得できるようにしました。
- Xで同じ投稿の後続応答に画像が追加された場合、その追加分も収集するようにしました。
- Xの大量件数の確認待ち中も初回の取得データを保持し、収集データへの登録完了を確認してから破棄するようにしました。別の収集ジョブの遅延応答は除外します。
- Threadsのカルーセル子一覧が複数ページに分かれる場合に、追加ページを取得する処理を加えました。
- 「不足分を再収集」を追加しました。前回状態を退避し、再走査で見つかった未登録の画像・動画だけを保存候補にします。
- 投稿の抽出件数やXの画面表示との比較を診断ログへ追加しました。

## 確認した範囲

- X: 自分のアカウントの20画像投稿で実保存を確認。以前取りこぼしていた他人のアカウントでも、20画像投稿2件の全画像を保存できることを確認しました。
- Bluesky: 自分の10画像投稿を収集し、途中停止後に5ファイルずつ保存。同じ投稿が3つのZIPをまたぐ場合も、10画像が欠落・重複なく保存されることを確認しました。
- Threads: 自分の20画像投稿と10画像投稿の実保存を確認しました。
- 提供されたZIPの画像はすべて画像として読み込み、バックアップの件数・画像番号・保存位置と照合しました。対象投稿に関する保存失敗はありませんでした。
- 自動テストは全29ファイル・107項目、JS/CJS全46ファイルの構文チェックが成功しています。

## 継続する制限

- Threadsで他人のアカウントから画像を取得できない問題は、今回の複数画像対応とは別の課題として残っています。フォロワー数が原因とは確定していません。
- 他人のBlueskyの10画像gallery投稿は、実機サンプルでの追加確認待ちです。
- Xの画面が提供しない古い履歴、削除・非公開投稿の取得を保証するものではありません。
- Xの既知の取りこぼしは実機で改善しましたが、初回応答消失の競合が昨日の症状の原因だったと断定したわけではありません。
- 「不足分を再収集」は未登録メディアの補完です。既存のダウンロード失敗の自動修復機能ではありません。古いバックアップで個別キーが残っていない過去分は、再取得される場合があります。

## 更新方法

1. 収集・ZIP保存を止め、必要に応じて設定からJSONバックアップを保存します。
2. 既存の拡張フォルダへ上書きし、Chromeの拡張機能管理画面で再読み込みします。
3. **開いているXのタブも再読み込みしてください。** ファイルの上書きだけではページ内の古い収集コードは入れ替わりません。

保存先は引き続き別タブで選択します。「常に許可」を選んでいない場合、選択肢がない場合、許可内容が不明な場合は、連続ZIP保存が終わるまで選択タブを閉じないでください。
