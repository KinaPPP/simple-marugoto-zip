# シンプルまるごとZIP / simple-marugoto-zip

SNSユーザーが投稿した画像・動画をまとめて収集し、`images/` と `videos/` に整理したZIPとして保存するChrome拡張機能です。

**v1.0.0はX（旧Twitter）向けの初回正式版です。** Bluesky / Threads は将来Providerとして追加できる構造だけ先に用意しています。

## 主な機能

- **初期設定と分割**: 新規インストールでは手動収集を初期値とし、自動収集も選択できます。ZIPの自動分割は300 MBか300メディアの早い方。10ファイル分割と設定画面の疑似429ボタンを廃止しました。以前に選んだ収集モードはそのまま維持され、旧版の10ファイル分割で停止したZIPジョブも続きを保存できます。
- **アイコン刷新（v0.0.22）**: 青／緑＋白のデザインを採用。小さい拡張ツールバー用の16px版は独立して図形を簡略化し、収集中・ZIP中・完了のバッジを見分けやすくしました。アイコン用SVGを `icons/` に同梱します。
- **シンプルな設定画面（v0.0.22）**: ZIP／JSONを設定タブにドロップするだけで、未登録のアカウントを自動追加。既存のアカウントは変更しません。重複がある場合だけ上書きボタンを表示し、上書き・全体置換は画面内の「いいえ／はい」で再確認します。
- **全データ初期化（v0.0.22、v0.0.23で文言整理）**: 設定タブ最下部の「すべて削除」でシンプルまるごとZIP自身の収集・保存情報、共通設定、IndexedDBの保存先ハンドルと待機アラームを削除。確認ボタンは左「いいえ」、右「はい、削除する」。実ファイルやChrome本体のログイン、ほかの拡張機能には触れません。

- **ZIP内へのアカウント状態同梱（v0.0.21）**: すべての分割ZIPに `ユーザー名/backup-state.json` を含めます。各ZIPの時点で保存が確定した位置が記録され、途中のZIPを復元しても以降を保存済みと扱いません。JSONはZIP内でDEFLATE圧縮します（非対応環境は無圧縮）。
- **拡張全体のJSONバックアップ（v0.0.21）**: 設定タブの先頭から全アカウントの収集・ZIP状態と共通設定を書き出し。ZIP/JSONを設定タブにドロップしてプレビューし、既存優先の追加、対象アカウント置換、全体置換を選べます。
- **自動／手動スクロール収集を切り替え**: 対象ユーザー欄の直下で選択し、選択内容を全アカウント共通で記憶します。手動時は拡張からスクロールを送信せず、Xの `/media` 上でユーザー自身が読み込んだメディアの通信を収集します。手動収集の終了は青い「収集を完了」を明示的に押してください。
- **新規分だけチェック（v0.0.20）**: 前回収集してZIP保存まで完了したアカウントで、ポップアップの「新規分をチェック」を利用できます。前回最も新しかったメディア投稿IDを境界として、新しく追加された投稿の画像・動画だけを別の収集ジョブにまとめます。自動・手動どちらでも使えます。
- **保存先フォルダを1回だけ選択**: 対応環境ではZIP保存開始時にフォルダを1回選び、分割された `001 / 002 / 003 ...` を同じフォルダへ連続保存します。保存先ハンドルは同じ収集作業のレジュームでも再利用します。
- **大量アカウント警告**: Xの `/media` 上部に表示されるメディア件数を取得できた場合、1000件以上なら収集開始前に長時間処理の確認を出します。
- **完了チェック表示**: ZIP保存完了時はツールバーに緑の `✓` を表示し、拡張アイコンを押して確認するまで保持します。次の収集／ZIP処理を開始した場合も自動解除します。
- **設定値の記憶**: 画像/動画、ZIP分割、5ファイル/無制限の選択を次回も引き継ぎます。初回のみ「5ファイル（動作確認）」が既定です。
- **待機時ツールバー整理**: 過去のZIPエラーは赤い `!` として常駐させず、実際に処理中の状態だけをツールバーへ表示します。
- **レスポンス待ちペーシング**: 一定間隔で盲目的にスクロールせず、X自身の `UserMedia` 等の通信開始・終了を監視し、レスポンス処理後に間隔を置いて次へ進みます。通信が発生しない場合だけ低頻度で最下部を再確認します。

- Xのプロフィール / メディア / 投稿ページから対象ユーザーを自動判定
- 対象ユーザーの `/media` タイムラインを収集し、X自身のUserMedia等の通信完了を待ってから次のスクロールへ進む低負荷ペーシング
- 画像はX CDNの `orig` を優先
- 通常動画とアニメーションGIFは最高ビットレートのMP4を優先
- ファイル名は `{Tweet ID}_{投稿内番号}.{拡張子}`
- ZIP内部を `ユーザー名/images/` と `ユーザー名/videos/` に分類
- 自動（300 MBまたは300ファイル） / 500 MB / 1 GB / 500ファイル でZIP分割
- 収集進捗を `chrome.storage.local` に保存
- 手動停止 / Chrome再起動後のレジューム
- XのHTTP 429検知時は強引に再試行せず待機
- 完成済みZIPには追記せず、次のZIP番号から再開

## 新規分チェック

1. 前回のメディア収集とZIP保存を完了したアカウントのページでポップアップを開き、「新規分をチェック」を押します。前回ZIP保存が未完了の場合はボタンを有効にしません。
2. **自動モード**: 新しいメディアから前回の投稿へ向かって低負荷ペーシングで確認します。**手動モード**: Xの `/media` を上から自分でスクロールしてください。前回の投稿位置が確認できれば、どちらも通信が落ち着いたあと自動終了します。
3. 新規メディアがあれば今回の差分だけを表示し、ZIP保存できます。以前選択した保存先フォルダを、Chromeの権限が残っている限り再利用します。新規の画像／動画をすべてZIP保存するまでは次の差分チェックは開始しません。
4. 新規0件なら前回の収集結果とZIP進捗を復元し、「新規メディアはありません」と表示します。
5. 途中でやめたい場合は「停止」。ZIP保存を始めていなければ、ステータス領域の「前回に戻す」で今回の差分だけを破棄できます。保存済みZIPは削除されません。

**注意**: 旧版では画像だけ／動画だけを別々に保存した履歴を完全には保持していません。差分チェック前に、必要な種類のZIPを保存済みか確認してください。前回の境界投稿が削除されている、XのWeb画面から古い投稿が得られない、投稿順が変わる等の場合、全件の差分検出を保証するものではありません。v0.0.21以降のZIPには復元用JSONが入りますが、v0.0.20以前のZIPには入っていません。

オフライン回帰テスト: `node tests/delta-collection.test.cjs`（Xへの通信なし）。

## バックアップ状態のZIP同梱と全体JSON（v0.0.21）

**アカウント別ZIP:** v0.0.21以降に新しく保存したすべての分割ZIP内に `ユーザー名/backup-state.json` が入ります。ZIP分割の「500ファイル」は**メディアの数**で、JSONは別の1ファイルです。収集済みメディア情報（投稿ID、種類、CDN URLなど）も格納するため、数万件を収集したアカウントでは小さなZIPでも状態JSONの容量が増える場合があります。圧縮して格納しますが、分割ごとに繰り返し含まれます。

**全体JSON:** 設定タブの上部で「JSONをエクスポート」を押します。各アカウントの現在の状態、差分チェック中なら退避している前回状態、画像／動画等の共通設定を保存します。保存先フォルダのアクセス権は移植できないため、別PCでは初回保存時に選び直してください。

**復元（v0.0.22）:** 設定タブの「ZIP／JSONから復元」にファイルをドロップ（ファイル選択でも可）すると、**既存アカウントはそのままで未登録アカウントだけを自動で追加**します。新規・既存の件数を短く表示します。既存アカウントを読み込んだファイルの内容で上書きしたい場合だけ「同じアカウントを上書き」を押し、画面内の「いいえ／はい、置き換える」で確認します。「詳細な復元操作」から全体JSONの全体置換を選ぶこともできます。途中ZIPからの復元は「そのZIPまでの保存記録」で、以前の分割ZIPのファイル本体が存在するかは検証しません。

**全データ初期化（v0.0.22）:** 設定タブ最下部にあります。全アカウントの履歴・設定に加えて保存先フォルダの記憶を消去します。実際に保存したZIP、エクスポート済みJSON、Chromeのログイン情報とダウンロード履歴は削除しません。収集またはZIP作成の実行中には初期化できません。操作を取り消せないため、必要なら先に全体JSONをエクスポートしてください。

**秘密情報を含めない:** APIキー、アクセストークン、Cookie、パスワード、保存先ハンドルや任意のストレージ項目はバックアップしません。収集対象のアカウント名、投稿ID、CDN URLは含まれますが、保存先のフォルダ名・アクセス権は含まれません。ZIP／JSONを第三者に渡す際は内容を確認してください。メディア取得URLが失効している場合は再収集が必要です。

**移行テスト:** 普段のPCに既存の拡張を上書き更新し、JSONをエクスポート。未導入PCへv0.0.21を読み込み、設定画面でインポートしてください。以前に作成したv0.0.20以前のZIPには状態ファイルが無いため、ZIP単体復元をテストするときはv0.0.21で新しいZIPを作ってください。

オフライン回帰テスト: `node tests/backup-restore.test.cjs`（分割ZIPの状態ファイル・CRC・全体JSON・機密項目の混入防止）。

## 疑似429の回帰テスト（開発者向け）

正式版候補では、設定画面から疑似429を発生させる診断UIを削除しています。疑似429の処理は `tests/simulated-429.test.cjs` に開発用回帰テストとして残し、Xへ余計な通信を発生させずに、429時の停止・待機・復帰・手動モード維持を検証します。

ローカル回帰テスト: `node tests/simulated-429.test.cjs`（Node.jsが必要。Xへの通信なし）。

## インストール

1. このフォルダを任意の場所へ展開します。
2. Chromeで `chrome://extensions/` を開きます。
3. 右上の「デベロッパーモード」をONにします。
4. 「パッケージ化されていない拡張機能を読み込む」を押します。
5. `simple-marugoto-zip` フォルダを選びます。

## 使い方

1. ChromeでXへログインして、保存したいユーザーのプロフィールまたは `/media` を開きます。
2. 拡張アイコンを押し、対象ユーザーと「収集方法」を確認します。**初期設定は手動**。必要な場合はポップアップ内で自動へ切り替えられます。
3. 「メディアを収集」を押します。対象の `/media` を開き、必要に応じて初回読み込みのため再読み込みします。
4. **自動の場合**: X側の関連通信を待ちながら自動で下へ進みます。最終確認の間は「収集の最終確認中…」と表示し、完了後にZIP保存が使用可能になります。
5. **手動の場合**: Xの `/media` タブを自分で下へスクロールし、必要な範囲を読み込みます。最後まで確認したら拡張を開き、青い「収集を完了」を押します。手動収集中は時間経過だけで勝手に「完了」になりません。
6. 画像／動画、ZIP分割、ダウンロードファイル数を選び「ZIPで保存」を押します。

手動モードでは途中で「停止」を押すと、従来どおり収集済みの範囲をZIP保存できます。再開も可能です。読み込みがまだ進行中の場合、「収集を完了」は最大8秒ほど通信・収集内容の保存を確認し、終わらなければそのまま収集を続けて再操作を案内します。初回や再収集時に上から確認したい場合はXの画面で先頭へ戻してください。

> 画像は常にXから取得可能な原寸解像度を優先して保存します。画像によってはファイルサイズが大きくなる場合があります。

> 「動画」にはX上のアニメーションGIF（MP4形式で配信されるもの）を含みます。

## 保存先フォルダ（v0.0.15）

大きなZIPは、保存先フォルダへ順次ストリーミング書き込みします。500件級でも全メディアを一度にメモリへ保持しないため、v0.0.10/11より大容量保存の安定性を高めています。


File System Access APIを利用できるChromeでは、「ZIPで保存」を最初に押した時に保存先フォルダを選択します。同じ収集作業で生成される分割ZIPは、その後ダイアログを繰り返さず同じフォルダへ保存します。

- 5ファイル（動作確認）で一時停止しても、次回の「ZIP保存を再開」は同じフォルダを再利用します。
- フォルダ権限が失われた場合は、再開時に保存先を再選択します。
- 分割ZIPの連続保存中は、選択済みフォルダのハンドルを同一実行内で使い回し、ZIPごとの再選択を避けます。
- File System Access APIを利用できない場合は、従来のChromeダウンロード方式へフォールバックします。
- 保存先の絶対パスやSNSパスワードは保存しません。Chromeが発行するフォルダハンドルのみを拡張機能のIndexedDBへ保持します。


## ポップアップ内の確認UI（v0.0.15）

1000件以上の大量メディア警告と「進捗をリセット」の最終確認は、Chrome/X側の標準ダイアログを使わず、ポップアップ中央のステータス領域へ表示します。確認中もポップアップの高さは変えません。

- 大量件数警告: 左「キャンセル」 / 右「続ける」
- 進捗リセット: 左「やめる」 / 右「リセット」
- リセットは収集・ZIPの進捗情報だけを削除し、既に保存済みのZIPファイルは削除しません。

ZIP保存完了後は、File System Access APIで選択した保存先の**フォルダ名**をステータス領域へ表示します。ブラウザの制約上、絶対パス表示やExplorerを自動で開く処理は行いません。

## ZIP例

```text
ppp200x_20260919_230500_media_001.zip
└─ ppp200x/
   ├─ images/
   │  ├─ 2101040138784829824_1.jpg
   │  └─ 2101040138784829824_2.jpg
   ├─ videos/
   │  └─ 2101189548885831967_1.mp4
   └─ backup-state.json
```

## 重要な制限

- Xの公式APIを使わず、**X自身のWebページが取得する `UserMedia` GraphQLレスポンスを監視**しています。X側の内部仕様変更で動かなくなる場合があります。
- 初回フル収集は `/media` を遡る方式です。前回ZIP保存済みなら新規分チェックで再走査を減らせますが、XがWeb画面へ返さない投稿を補完する処理はありません。
- 手動収集の「完了」はユーザーの判断です。ページが読み込まなかった投稿まで取得済みと保証するものではありません。
- 手動モードでもXのWebレスポンスを監視します。自動スクロールを行わないことは、Xによる利用許可・アカウントへの措置がないことの保証にはなりません。利用前にサービスの最新の規則を確認してください。
- 自動収集の完了判定は「一定時間新しいメディアが追加されない」「関連通信が落ち着いている」「ページ高さが複数回安定した」を組み合わせた安全側のヒューリスティックです。
- 大量メディアのZIP作成はメモリを使います。特に1 GB分割はPC環境によって負荷が大きくなる場合があります。まずは「自動」を推奨します。
- Xのアクセス制限・利用ルールは変更される場合があります。429等を検知した場合、本拡張は制限回避を試みません。

## テストで確認してほしいポイント

- 対象ユーザーが正しく表示されるか
- 自動モードで `/media` へ移動し、読み込みを待ちながらスクロールするか
- 手動モードで自動スクロールせず、自分のスクロールで画像／動画数が増えるか
- 画像数 / 動画数が増えるか
- 同一Tweetの複数画像が `_1`, `_2` で保存されるか
- animated GIFが動画としてカウントされるか
- 「停止」→「続きから再開」が動くか
- ZIP内部の `images/` / `videos/` が正しいか
- 500ファイル等の分割で `_001.zip`, `_002.zip` と進むか

詳しい設計は `docs/SPEC.md` を参照してください。

## 5ファイル・動作確認保存

ポップアップの「ダウンロードファイル数」で **5ファイル（動作確認）** を選ぶと、1回のZIP保存につき最大5件のメディアだけを保存して安全に一時停止します。もう一度「ZIP保存を再開」を押すと、保存済みの続きから次の最大5件を処理します。

この上限はメディアの**収集件数**ではなく、ZIPへ実際に保存するファイル数のテスト用上限です。通常利用時は「無制限」を選択してください。

### Xタブへの自動接続

拡張機能を読み込む前から開いていたXタブでも、その場で必要なスクリプトを自動注入して接続を試みます。通常はXタブを手動で再読み込みする必要はありません。


## テストポイント

- 収集中に「停止」を押すと、その時点までに収集したメディアをZIP保存できます。
- ZIPを5ファイルで保存後も収集進捗は残り、「収集を再開」で続きを取得できます。
- ポップアップは固定高で、通常はスクロールバーなしで全操作を表示します。


## ZIPファイル名

ZIPは `ユーザー名_YYYYMMDD_HHmmss_media/images/videos_連番.zip` 形式で保存します。
同じ保存作業をレジュームした場合、日時部分は初回のZIP保存開始時刻を維持し、`001`, `002`, `003` ... と連番だけが進みます。


## ツールバーアイコンの状態表示

- 通常の待機中は青アイコンのみ。未確認のZIP保存完了だけは緑アイコン＋ `✓` で保持します。
- ZIP保存中は緑アイコン＋1%単位の数字（`0`〜`99`）を表示します。100%の3桁表示は使わず、完了時は `✓` を表示してユーザー確認まで保持します。
- ホバー文言は10%刻みの目安で更新し、進捗更新によるツールチップ消失を減らします。
- 保存ダイアログでキャンセルした場合はエラーではなく安全な一時停止として扱います。


ポップアップは保存ダイアログ等で閉じる場合がありますが、バックグラウンド処理は継続します。Chromeツールバー上の拡張アイコンでも状態を確認できます。

- 通常: **青アイコン**
- メディア収集中: 青アイコン + `収`
- 大量件数の確認待ち: 青アイコン + 黄色の `確`
- Xの429待機: 青アイコン + `待`
- ZIP保存中: **緑アイコン** + `0`〜`99`
- ZIP保存完了（未確認）: **緑アイコン** + `✓`。拡張アイコンを押してポップアップを開くまで保持
- ZIP保存の続き待ち: 青アイコン + `続`
- エラー: 青アイコン + `!`

アイコンへマウスを重ねると、処理件数や進捗率などの詳細をツールチップで確認できます。

ZIP保存開始後は、収集済みURLを使ってOffscreen Document側で画像・動画取得とZIP生成を続行するため、**Xの元タブを別ページへ移動したり、別タブを操作してもZIP保存処理には影響しません**。ただしChrome自体を終了すると処理は停止します。

ZIP保存中は誤操作防止のため、メディア収集・収集停止・レジューム・取得対象・ZIP分割など、ZIP中に変更すべきでない操作をロックします。「中止」はZIP処理専用です。


### ZIPファイル名

取得対象に応じて次の種類名を含めます。

- 画像＋動画: `ユーザー_YYYYMMDD_HHmmss_media_001.zip`
- 画像のみ: `ユーザー_YYYYMMDD_HHmmss_images_001.zip`
- 動画のみ: `ユーザー_YYYYMMDD_HHmmss_videos_001.zip`

同じ保存ジョブの連番ZIPでは日時と種類名を固定します。
