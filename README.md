# シンプルまるごとZIP / simple-marugoto-zip

X（旧Twitter）・Bluesky・Threadsの投稿画像・動画を収集し、`images/`・`videos/` に分けてZIPで保存するChrome拡張機能です。作者 **KINA**、ライセンス **MIT**。現在のバージョンは **v1.3.0** です。

## 主な機能

- Xの従来の混在メディア表示と、新しい動画／画像の分割表示に対応。新UIの**自動収集**では動画ページから画像ページへ移動し、結果を統合します。旧表示に戻す設定も選択できます。
- Blueskyの公開投稿をAPIで取得。アカウントのログインやAPIキーは不要です。投稿者のPDSにある画像・動画Blobを優先します。
- Threads APIの自分の投稿と、アプリ権限で閲覧を認められた公開プロフィールの画像・動画・複数メディア投稿を収集します。**一般公開アカウントの取得はMetaのアクセス審査状況に依存します。**
- 画像のみ・動画のみ・両方でZIP保存。**自動分割は300 MBまたは300メディアファイル**の先着条件。500 MB／1 GB／500ファイルも選べます。
- 中断・再開、前回ZIP保存後の新規分チェック、アカウント別状態のバックアップと復元。
- 各ZIP内に `backup-state.json` を同梱。設定画面から全体／SNS別／アカウント別のJSONを書き出し、ZIP／JSONのドラッグ＆ドロップで復元できます。選択したSNS・アカウントのみ復元したり、個別の保存状態を削除することもできます。

**最初は5ファイル（動作確認）が選択されています。** 全件をZIP保存する場合は「無制限」に変更してください。

## インストール・更新

1. 配布ZIPを展開します。
2. Chromeで `chrome://extensions/` を開き、「デベロッパーモード」をONにします。
3. 「パッケージ化されていない拡張機能を読み込む」で、ZIP内の `simple-marugoto-zip/` フォルダを指定します。

**更新前に、設定画面から全体JSONをバックアップしてください。** 今使っている拡張を削除せず、同じ展開先のファイルを更新して拡張を「再読み込み」すると、通常はこれまでの収集状態を維持できます。別フォルダから独立した拡張として追加した場合はデータが分かれるため、必要ならJSONをインポートしてください。ZIPの実ファイルや保存先フォルダ権限はJSON経由で自動移動しません。


## 設定画面

設定は用途ごとに **「対応サービス」「バックアップ・復元」「保存データ」** の3タブへ分けています。初回セットアップやSNS固有設定は「対応サービス」、ZIP／JSONの退避と復元は「バックアップ・復元」、アカウント別状態の削除や全初期化は「保存データ」を使います。最後に開いていたタブをこのChrome内で記憶します。

## Xの使い方：新旧UI両対応

対象ユーザーのプロフィールまたはメディアページを開き、拡張アイコンから「メディアを収集」を選びます。**収集方法の初期値は手動**です。手動モードでは自分でXのページをスクロールし、必要な範囲まで読み込んで「収集を完了」を押します。新UIで両方の種類を手動収集する場合は、自分で動画／画像ページを切り替える必要があります。

自動モードに切り替えた場合、初期設定ではXの画面は変更せず、新UIの動画 `https://x.com/ユーザー/media` → 画像 `https://x.com/ユーザー/media?filter=photo` を順に巡回します。旧UIが有効な環境では画像・動画が混在する従来の1ページ収集を行います。両方の収集情報は同じアカウントへ重複なしで統合されます。

設定の「対応サービス」→「X」から「プロフィールタブを旧表示に戻す」をONにすることもできます（**初期値OFF**）。「新UIから収集」は初期値ONで、**両方ONでも構いません**。旧表示への変更はXタブの再読み込みが必要です。Control Panel for Twitterなどで既に旧UIにしている場合、本拡張側の旧UI化は不要です。Xが内部仕様を変更した場合、旧表示の復元が機能しなくなる可能性があります。

Xから429などのアクセス制限を受けた場合は収集を一時停止します。待機解除時刻に対象タブが利用できれば自動再開を試みますが、X側がエラー画面などになっていると**青ボタンからの手動再開が必要**です。時刻は利用可能になる目安で、アクセス制限が完全に解除された保証ではありません。強制再試行を繰り返さないでください。

実機テストの詳細： [X新旧UIの検証](docs/X_NEW_UI_TEST.md) / [従来X版の詳細](docs/X_V1_REFERENCE.md)。

## Blueskyの使い方

1. `https://bsky.app/profile/アカウント名` を開いて拡張アイコンを押します。
2. 「メディアを収集」で公開APIから本人の投稿に付いた画像・動画を収集します。ブラウザ画面をスクロールする必要はありません。PDSへのアクセス権が必要な場合は、Chromeが表示したそのPDSの権限だけ許可してください。
3. 取得したいメディアの種類と分割方法を選んでZIP保存します。画像・動画をまとめて全件保存するときは「無制限」に切り替えてください。

元データは投稿者のPDS上のBlobを優先します。画像Blobが取得できない場合は表示用の大きな画像を試みます。元動画が取得できない場合は、別の動画へ勝手に変換せず失敗として扱います。投稿前の原本を復元するものではありません。リンクカードのサムネイル、他人のリポストや引用元のメディアは対象外です。PDSによって取得可否に差があります。詳しくは [Blueskyテストと既知の制限](docs/BLUESKY_BETA_TEST.md) を参照してください。

## Threadsの使い方

**認証専用サーバーはありません。** 利用者自身がMetaのThreadsアプリを用意し、[Threadsトークン 取トーくん](https://kinappp.github.io/threads-token-tool/)等で長期アクセストークンを取得します。設定の「対応サービス」→「Threads」に貼り付けて「トークンを保存」を押してください。App SecretはシンプルまるごとZIPへ入力しません。トークンは**そのChromeプロファイルの `chrome.storage.local` に平文保存**します。Chromeプロファイルへアクセスできる人・ソフトから読み取られる可能性があるため、共有PCで利用する場合は、使用後に保存トークンを削除するなど取り扱いに注意してください。

トークンの**自動更新は初期値ON**で、登録直後は期限を推定表示し、約24時間以上たってから最初の自動更新で残存期限を確認します。その後は残り約30日からChrome起動時／アラームで更新を試みます。「今すぐ更新」ボタンもあります。Chromeを長期間起動しなかった場合、Meta側で許可を取り消した場合、短期・期限切れトークンを貼り付けた場合は、再接続が必要です。初回に認証する利用者自身のMetaアプリの権限・審査状態が適用されます。`threads_basic` は自分の投稿、`threads_profile_discovery` は許可された公開プロフィールの検索・投稿取得に必要です。**公開プロフィールの取得範囲は、利用者自身のMetaアプリに付与された権限・アクセスレベル・審査状態に依存します。**

1. 認証後に `https://www.threads.com/@ユーザー名` を開き、拡張アイコンから「メディアを収集」を押します。ページをスクロールする必要はありません。
2. Threads Graph APIのページ送りで `IMAGE` / `VIDEO` / `CAROUSEL_ALBUM` を収集します。テキストのみ投稿や `REPOST_FACADE` は対象外です。動画はAPIが返す配信URLのデータを保存し、投稿前の原本・画質を保証するものではありません。
3. 画像・動画の種類、分割単位を選択しZIPを作成します。取得対象CDNにChromeの権限確認が出た場合は必要な配信先のみ承認してください。

**制限・注意：** `profile_lookup` / `profile_posts` は、アプリが許可された公開アカウントのみ対象です。Metaの審査や公開アカウントの条件で失敗したら、仕様を迂回せず自分のアカウントでテストしてください。Graph APIの429は最低15分停止し、利用可能時刻以降にユーザーが明示的に再開します。Threadsの配信URLには期限付きの署名が含まれる場合があり、保存前に無効になったら再収集が必要です。停止・復元・別PCへの移行後も、新PCではトークンを再登録してください。

## バックアップとプライバシー

設定画面の「JSONをエクスポート」は本拡張内のアカウント別の収集情報・ZIP進捗と一部の設定を書き出します。SNS別・アカウント別で部分保存したJSONは `partial:true` を含み、誤って全体置換に使うことはできません。個々のZIP内の `backup-state.json` は**そのZIPを保存した時点の当該アカウントの状態**です。画像・動画の実ファイルまで含めて一括移行するものではありません。

ZIP／JSONのインポートは**既存データを残して追加**が初期動作です。同じアカウントを置き換える場合は確認が必要で、別々のZIPの進捗を自動的に合算する機能ではありません。 差分ZIPは前回までの累計状態をスナップショットとして内包するため、最新の差分ZIP 1個だけでもその時点の累計件数を復元できます。古い全件ZIPを読み込めば、その時点を基準に以後の新規分を取り直せます。

バックアップにはアカウント名、投稿ID、メディアURLなどを含みますが、**APIキー、アクセストークン、Cookie、パスワード、保存先フォルダへのアクセス権は含めません。** 共有する場合は収集履歴が分かる情報を含むことに注意してください。詳しくは [PRIVACY.md](PRIVACY.md) を参照してください。
